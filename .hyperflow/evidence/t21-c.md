## Fixture and contract changes

`backend/test/utils/e2e-app.ts` starts its own Mongo process on an ephemeral loopback port, sets synthetic configuration before the dynamic AppModule import, and changes to an empty owned directory before ConfigModule can read `.env`. The Nest application uses real middleware, validation and guards. Mail uses the existing rendering methods with an in-memory send sink; no SMTP transport is created. Four deterministic users and roles are reset in the owned database. Throttle counters and timers are reset between browser cases, while actual endpoint throttling remains installed. Cleanup closes Nest, stops Mongo, restores the previous process directory/configuration and removes the empty fixture directory. Database reset visits the owned collections and deletes their fixture records; it never selects an arbitrary database.

`backend/test/utils/browser-server.ts` exposes ready/reset over parent-child IPC. The Playwright worker forwards only PATH, HOME, TMPDIR, NODE_ENV=test and its ts-node project path. One browser worker owns backend port 5107, and Playwright owns production frontend port 3107 with server reuse disabled. Every test gets a fresh browser context and real password-issued cookies. The second session is also issued through the real endpoint. Fixture metadata is excluded from the strict login DTO.

## Design and coverage limits

The persistence repair is constant-size work and stores one boolean hint. It does not authorize protected access; the existing server profile validation still supplies the user. Tests cover current and malformed legacy state, anonymous failure recovery, role-specific destinations and repeated reload. They do not prove every browser storage corruption is recoverable.

Fixture reset is O(c + n) database work for c owned collections and n fixture records. Password hashes are precomputed once per suite for four accounts. Permission reconciliation uses sets for O(p + q) comparison and only the necessary grant/revoke requests; output and I/O remain linear in changed permissions. Single-worker browser execution avoids shared reset races. No performance gain is claimed or benchmarked.

The 49 cases comprise the original 20 sidebar, 13 session and 10 role tests plus six focused persistence, return-path, anonymous-401 and Arabic desktop/mobile regressions. Screenshots were inspected for the Arabic desktop/mobile sessions and the network-toast reproduction. The 44 anonymous frontend-only cases from T21-D remain separate evidence; they were not rerun unchanged here. Automated axe, full lifecycle and settings/users coverage are not implied by this pass.
