## Operational cost and recovery

Fixture reset scans and deletes the seeded collections, O(number of fixture documents) database work with a bounded number of collection requests. Seed preparation hashes four known users once per fixture boot; per-test resets reuse those prepared values. Keep one worker for shared mutable state. Cwd and process environment are process-wide, so parallel fixture boot inside the same process is incompatible with the current design. Expanding concurrency would need per-process ownership and separate ports/databases, not a CI worker-count increase.

Export and hashing cost O(source bytes) I/O plus O(file count) inventory memory. A clean install and three image builds dominate disk/network use. The prior report measured approximately 14.5 GB free after cleanup; this is historical, so the executor must check again before capture. Keep fixture temp/cache directories outside the source tree and preserve workspace-local dependencies if reusing an installed snapshot. Preserve the original failure code through cleanup. Confirm child processes, owned ports, database directories, Compose containers/networks/volumes and synthetic state files are gone.
