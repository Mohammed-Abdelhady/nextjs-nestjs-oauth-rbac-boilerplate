## Accepted revised plan and results

Root accepted a revised scope after T21-B's single targeted repair left eight cases unresolved. The previous iteration history and failed traces remain in `t21-b.md` and `t21-b/`.

T21-B-F3/F4: blur validation inserted an error between mouse-down and mouse-up, moving lower form links out from under the pointer. The first repair proved the cause on the login forgot-password link but exposed the same behavior on the forgot-page return link. T21-D uses one stable, typed `preventNavigationBlur` handler on exactly three links: login → forgot-password, forgot-password → login, reset-password → login. It prevents the primary mouse-down focus transfer; the actual link click, href and keyboard activation remain native. Middle-button events are untouched; modifier flags are not changed. Native auxiliary/modifier new-tab navigation was not separately exercised in this matrix.

All three links now have first-activation regression coverage while their initial input is focused. Desktop projects use actual mouse clicks; mobile projects use actual touchscreen taps through the shared action helper. Keyboard Enter and Tab navigation remain asserted. All four projects pass.

T21-B-F5: the installed React Hook Form implementation calls `_focusError()` and then schedules `setTimeout(_focusError)` on invalid submission (`node_modules/react-hook-form/dist/index.esm.mjs`, lines 2205–2206). The test was pressing Tab immediately after a second invalid submit and racing that scheduled focus. T21-D preserves the initial empty-submit error/focus assertion, enters a malformed address, validates through actual Tab/blur, checks the submit button focus, then Tabs to the return link and presses Enter. This checks real client validation and onward keyboard behavior without patching the library, disabling error focus, inserting sleeps or dropping assertions. All four projects pass.

F1/F2 remain verified: every page starts without the intl-provider crash, and all 16 page/locale/viewport checks pass the document language, direction, accessible form name and horizontal-overflow assertions. Four representative final screenshots were inspected: English desktop login, English mobile registration, Arabic desktop forgot-password, Arabic mobile reset-password. All 16 PNGs are saved in `t21-d/screenshots/`.
