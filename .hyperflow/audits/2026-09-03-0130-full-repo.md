## TL;DR

The code has a sound core (httpOnly strict cookies, hashed verification codes, whitelist validation, non-root containers) but ships with defects that block any production use: deactivated users can log back in, the production compose publishes MongoDB with a default password, OAuth state is never validated, and the backend typecheck and 8 of 11 test suites fail on a clean checkout. The frontend fails WCAG AA on contrast, labels and keyboard access, and the Arabic locale falls back to English across the admin area. The E2E suite targets selectors that no longer exist.

## Section R: Research summary (providers and CLI)

Observed: OAuth is hand-rolled fetch (google, github, facebook) with no PKCE, nonce or id_token verification; callback URL is a frontend page that POSTs the code to the backend, which is incompatible with Apple's required form_post; provider union is hardcoded in about 11 places; GET /api/auth/oauth/providers already exists and OAuthButtons renders from it.

Provider endpoints verified 2026-09-02 from discovery documents: Google, Microsoft (common tenant, PKCE recommended, validate iss per tid), Apple (client secret ES256 JWT, form_post, name only on first auth, no localhost redirect), LinkedIn OIDC, Discord, X (PKCE mandatory, codes expire in 30s), GitLab (self-managed base URL), Slack OIDC (nonce mandatory), Twitch OIDC. Spotify dropped: /me no longer returns email.

Packages (npm, 2026-09-02): otplib 13.5.0, @simplewebauthn/server 14.0.0 (node >=20), openid-client 6.8.7, oauth4webapi 3.8.7, jose 6.2.10, @clack/prompts 1.7.0, commander 15.0.0 (node >=22.12), citty 0.2.2, giget 3.3.1, tsdown 0.22.14, @changesets/cli 3.0.1. passport is stale (0.7.0, 2023).

npm names available: create-auth-boilerplate, create-nest-next-auth, create-nest-next, create-fullstack-auth, create-auth-stack, create-nest-next-app, create-oauth-app. Taken: create-rbac-app.

Security references: RFC 9700 (PKCE recommended for confidential clients), OWASP ASVS 5.0 V6/V7/V10, \_\_Host- cookie prefix, custom header CSRF defence for cookie SPAs.

### Registry design (adopted)

Backend: OAUTH*STRATEGIES multi-provider token, dynamic OAuthModule.register(strategies); each strategy carries provider id, display name, env prefix, and id field; service resolves by lookup. Provider ids stored as linkedAccounts [{provider, providerId}] with a compound unique index. Generic OAUTH*\* error codes with details.provider. Frontend: /auth/oauth/providers returns [{ id, displayName }] and OAuthButtons, LinkedAccounts, callback pages render from it with a PROVIDER_META map keyed by id. Backend-side callback route sets the cookie and redirects, which also supports Apple form_post and server-side state and PKCE.
